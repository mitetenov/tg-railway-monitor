# tre.ge Telegram Ticket Monitor

Telegram-бот на Go для мониторинга железнодорожных билетов Грузии на tre.ge.
Откройте `/start` и нажмите «Добавить поиск», затем выберите дату, маршрут,
время отправления и класс.
Можно запустить несколько поисков одновременно: бот проверяет каждый каждые
60 секунд и присылает уведомление при появлении билетов или увеличении их числа.
Интерфейс — русский и английский, язык определяется из профиля Telegram.

## Запуск

```sh
cp .env.example .env
# Укажите BOT_TOKEN от @BotFather в .env
docker compose up -d --build
docker compose logs -f
```

Для опубликованного образа: `docker compose pull && docker compose up -d`.
Docker сохраняет настройки и состояние мониторинга в томе `data:/app/data`.
После перезапуска бот автоматически продолжает проверки без повторной рассылки
уже известных билетов. Подробности обновления и отката — в [DEPLOY.md](DEPLOY.md).

## Команды

| Команда | Действие |
|---|---|
| `/start` | Список поисков с кнопкой добавления нового |
| `/stop` | Остановить и удалить все поиски чата, сохранить язык |
| `/lang` | Кнопки выбора языка EN/RU |
| `/lang en`, `/lang ru` | Сменить язык текстовой командой |

На главном экране каждый поиск показан отдельной кнопкой с маршрутом, датой,
классом, выбранным рейсом и состоянием. Если активных поисков нет, бот сообщает об этом. Поиски
на паузе остаются в списке. В карточке поиска можно поставить его на паузу,
продолжить или удалить с подтверждением; остальные поиски продолжают работать.
Список разбит на страницы по восемь поисков. Из уведомления можно открыть
карточку соответствующего поиска.

Пауза сохраняет настройки и историю уведомлений. После продолжения неизменившиеся
места повторно не рассылаются. После окончания дня поездки по времени Грузии
поиск завершается автоматически; другие поиски и выбранный язык сохраняются.
Просроченные поиски на паузе удаляются при запуске бота или открытии списка.

Даты «сегодня», «завтра» и проверка прошедших дат используют **Asia/Tbilisi**.
Можно выбрать свою дату в формате `YYYY-MM-DD`, станции из списка с пагинацией
и класс `Any`, `Business`, `I`, `II`. Выбранная станция отправления исключается
из всех вариантов прибытия. После выбора станций бот предлагает рейсы
на выбранную дату: например, `08:00 · №812`, а также «Любое время».
Выбранный рейс фильтруется по времени отправления и номеру поезда. Время
используется как в ответе tre.ge, без перевода часового пояса.
Время и номера берутся из отдельного расписания tre.ge, поэтому можно выбрать
рейс, даже когда все билеты на него распроданы. Если расписание пусто или
недоступно, можно обновить его либо выбрать «Любое время». Кнопка «Обновить рейсы»
показывается только при ошибке загрузки или пустом списке.
Для маршрутов, отсутствующих в расписании tre.ge, бот показывает рейсы из наличия
с пояснением, что список ограничен поездами с билетами.
Отмена мастера возвращает к списку, сохраняя
существующие поиски; новый поиск добавляется целиком после выбора класса.
Старый единственный маршрут автоматически появляется в списке без потери
истории уведомлений.

Уведомление содержит доступные рейсы выбранного класса с учётом выбора времени
и поезда, время, число мест,
цену в GEL и ссылку на покупку. Уменьшение числа мест не вызывает уведомление.
После распродажи повторное появление билетов вызывает новое уведомление.
При ошибке API прежнее состояние сохраняется; при ошибке Telegram отправка
повторяется при следующей проверке. При частичной отправке нескольких сообщений
или сбое записи состояния возможна повторная доставка.

## Настройки окружения

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Обязательный токен Telegram |
| `DATA_DIR` | Каталог JSON-файлов; `data` локально, `/app/data` в Docker |
| `TICKET_SOURCE` | `trege` (по умолчанию) или `tre.ge`; регистр и пробелы по краям не учитываются |
| `TRE_API_BASE`, `TRE_API_KEY` | Необязательная замена адреса/публичного ключа tre.ge |
| `TRE_TIMETABLE_BASE`, `TRE_TIMETABLE_KEY` | Необязательная замена адреса расписания и публичного ключа веб-клиента tre.ge |
| `TELEGRAM_API_BASE` | Необязательный адрес Telegram API для локальных проверок |

Переменные процесса имеют приоритет над `.env`. Маршрут, дату, рейс и класс задают
через кнопку «Добавить поиск» на экране `/start`, отдельно для каждого чата.
Реальный токен для тестов не нужен. Для расписания бот автоматически получает
анонимный доступ tre.ge; аккаунт на сайте не требуется, токен хранится в памяти.

## Разработка

Нужен Go 1.27.3. Внешних Go-зависимостей нет.

```sh
go test -race -count=1 ./...
go vet ./...
go build -trimpath -o ticket-monitor .
./ticket-monitor --check
./ticket-monitor --version
./ticket-monitor
```

`--check` проверяет доступ на запись и встроенные ресурсы без обращения к сети.
Тесты проверяют мастер, HTTP/TLS-контракты, гонки запуска/остановки, восстановление,
ошибки API/доставки, фильтры классов/рейсов и 160 эталонных уведомлений из Python-версии.
Структура модулей — в [structure.md](structure.md), правила — в [AGENTS.md](AGENTS.md).

## Docker-образ

```sh
docker build --build-arg VERSION=$(cat version.txt) -t tg-ticket-monitor:local .
```

Go собирается в отдельном этапе, финальный образ — `scratch`. В нём только
статический бинарник, корневые сертификаты HTTPS и версия. Переводы, станции
и база часовых поясов встроены в бинарник. Бот работает от UID/GID **1000:1000**,
совместимого с существующими томами Python-версии.

Порядок сборки: манифест → постоянные файлы окружения → исходники → компиляция
с кешем BuildKit → версия. Документация, тесты, `.env`, данные и рабочие деревья
не попадают в контекст сборки. Обычная пересборка: `docker compose build`;
`--no-cache` нужен только для намеренного сброса кеша.
