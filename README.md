# tre.ge Telegram Ticket Monitor

Telegram-бот на Go для мониторинга железнодорожных билетов Грузии на tre.ge.
Выберите дату, маршрут и класс через `/start`: бот проверяет места каждые
60 секунд и присылает уведомление при появлении билетов или увеличении их числа.
Интерфейс — русский и английский, язык определяется из профиля Telegram.

## Запуск

```sh
cp .env.example .env
# Укажите BOT_TOKEN от @BotFather в .env
docker compose up -d --build
docker compose logs -f
```

Для опубликованного образа: `docker compose pull && docker compose up -d`.
Docker сохраняет настройки и состояние мониторинга в томе `data:/app/data`.
После перезапуска бот автоматически продолжает проверки без повторной рассылки
уже известных билетов. Подробности обновления и отката — в [DEPLOY.md](DEPLOY.md).

## Команды

| Команда | Действие |
|---|---|
| `/start` | Мастер: дата → отправление → прибытие → класс |
| `/stop` | Остановить проверки, удалить маршрут и состояние, сохранить язык |
| `/lang` | Кнопки выбора языка EN/RU |
| `/lang en`, `/lang ru` | Сменить язык текстовой командой |

После окончания дня поездки по времени Грузии мониторинг завершается автоматически; выбранный язык сохраняется.

Даты «сегодня», «завтра» и проверка прошедших дат используют **Asia/Tbilisi**.
Можно выбрать свою дату в формате `YYYY-MM-DD`, станции из списка с пагинацией
и класс `Any`, `Business`, `I`, `II`. Отмена мастера сохраняет прежний маршрут;
новые настройки применяются целиком после выбора класса.

Уведомление содержит все доступные рейсы выбранного класса, время, число мест,
цену в GEL и ссылку на покупку. Уменьшение числа мест не вызывает уведомление.
После распродажи повторное появление билетов вызывает новое уведомление.
При ошибке API прежнее состояние сохраняется; при ошибке Telegram отправка
повторяется при следующей проверке. При частичной отправке нескольких сообщений
или сбое записи состояния возможна повторная доставка.

## Настройки окружения

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Обязательный токен Telegram |
| `DATA_DIR` | Каталог JSON-файлов; `data` локально, `/app/data` в Docker |
| `TICKET_SOURCE` | Поддерживается `trege` (по умолчанию) |
| `TRE_API_BASE`, `TRE_API_KEY` | Необязательная замена адреса/публичного ключа tre.ge |
| `TELEGRAM_API_BASE` | Необязательный адрес Telegram API для локальных проверок |

Переменные процесса имеют приоритет над `.env`. Маршрут, дату и класс задают
через `/start`, отдельно для каждого чата. Реальный токен для тестов не нужен.

## Разработка

Нужен Go 1.27.3. Внешних Go-зависимостей нет.

```sh
go test -race -count=1 ./...
go vet ./...
go build -trimpath -o ticket-monitor .
./ticket-monitor --check
./ticket-monitor --version
./ticket-monitor
```

`--check` проверяет доступ на запись и встроенные ресурсы без обращения к сети.
Тесты проверяют мастер, HTTP/TLS-контракты, гонки запуска/остановки, восстановление,
ошибки API/доставки, фильтры классов и 160 эталонных уведомлений из Python-версии.
Структура модулей — в [structure.md](structure.md), правила — в [AGENTS.md](AGENTS.md).

## Docker-образ

```sh
docker build --build-arg VERSION=$(cat version.txt) -t tg-ticket-monitor:local .
```

Go собирается в отдельном этапе, финальный образ — `scratch`. В нём только
статический бинарник, корневые сертификаты HTTPS и версия. Переводы, станции
и база часовых поясов встроены в бинарник. Бот работает от UID/GID **1000:1000**,
совместимого с существующими томами Python-версии.

Порядок сборки: манифест → постоянные файлы окружения → исходники → компиляция
с кешем BuildKit → версия. Документация, тесты, `.env`, данные и рабочие деревья
не попадают в контекст сборки. Обычная пересборка: `docker compose build`;
`--no-cache` нужен только для намеренного сброса кеша.
