## Внесённые изменения

1. Включён `setup-go` cache с явным `cache-dependency-path: go.mod`. Отсутствие
   внешних модулей не отменяет пользы от кеша компиляции стандартной библиотеки,
   включая варианты с race detector. Ключ сохраняется между изменениями исходников;
   новая копия кеша не загружается в хранилище на каждом коммите. После изменения
   версии Go кеш создастся заново. [Поведение setup-go](https://github.com/actions/setup-go#caching-dependency-files-and-build-outputs).
2. Убран повторный vet из `go test`: отдельный `go vet ./...` сохранён,
   тесты запускаются с `-vet=off -race -count=1`. Результаты тестов не кешируются.
3. Из `docker-publish` убран запуск BuildKit. `imagetools` работает через CLI,
   который [предустановлен на ubuntu-24.04](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md).
   По базовому запуску это устраняет шаг длительностью 7 секунд и запуск
   дополнительного контейнера. Итоговое ускорение GitHub Actions ещё не измерено.
4. Версия проверяется один раз в обязательном `test`, до установки Go, и
   передаётся через job output. Ошибка версии теперь блокирует PR. Исключена
   зависимость версии от порядка завершения matrix jobs.
5. Добавлены таймауты: `test` — 5 минут, Docker build — 10, publish — 3.
   Улучшен вывод ошибки форматирования; ошибка самого `gofmt` также завершает шаг.
6. Actions закреплены по SHA, проверенным через refs официальных репозиториев;
   checkout не сохраняет Git credentials. Dependabot объединяет еженедельные
   обновления Actions в один PR. [Рекомендации GitHub](https://docs.github.com/en/actions/reference/security/secure-use),
   [настройки Dependabot](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference).
7. Retention записей Docker build ограничен одним днём, как и digest artifacts.
8. Убраны семь старых gitlinks из `.worktrees/`, ошибочно попавших в индекс без
   `.gitmodules`. Первый PR-запуск выявил, что они ломают cleanup credentials в
   checkout с `persist-credentials: false`. Локальные каталоги сохранены;
   `.worktrees/` уже исключён через `.gitignore`.

Локальный контрольный замер Go 1.27.3 на macOS arm64: одинаковая последовательность
`go vet` и `go test -vet=off -race -count=1` с пустым и затем прогретым `GOCACHE`.

| Состояние кеша | Wall time, vet + tests | CPU time, vet + tests | Исполнение самих тестов |
| --- | ---: | ---: | ---: |
| Пустой | 23,917 с | 58,323 с | 9,729 с |
| Прогретый | 10,655 с | 2,050 с | 9,708 с |

В этом замере кеш сократил wall time примерно на 55%, CPU time — на 96%.
Это локальное сравнение компиляции, а не прогноз итогового времени Linux CI:
GitHub дополнительно скачивает/сохраняет кеш, подготавливает runners и инструменты.
Стабильное время исполнения самих тестов подтверждает, что тесты запускались
повторно. Иммутабельный ключ в основном сохраняет стандартную библиотеку; после
изменения исходников пакет приложения компилируется заново.

## Что уже устроено хорошо

- PR запускает проверки без Docker Hub secrets; Docker собирается только на
  push в `main` и только после успешного `test`.
- Обе платформы собираются нативно, без QEMU, каждая ровно один раз. Перед push
  проверяются architecture, версия, UID `1000:1000`, ресурсы и writable storage
  в контейнере с read-only filesystem и без сети.
- Публикуется проверенный Image ID, а release manifests собираются по digest
  только после успеха обеих платформ. Промежуточные теги уникальны для run/attempt.
- Параллельные PR-запуски одной ветки отменяются; публикация `main` не прерывается
  новым push. GitHub token ограничен `contents: read`.
- Статический `scratch` image, allowlist в `.dockerignore`, отдельные кеши по
  архитектуре и позднее добавление версии уже уменьшают работу при пересборке.
- `main` требует успешный `test` на актуальной базе; force-push запрещён.
  Secret scanning и push protection включены.

## Следующие улучшения по приоритету

| Приоритет | Улучшение | Практический результат / ограничения |
| --- | --- | --- |
| Высокий | Тег `sha-<commit>` и OCI label `org.opencontainers.image.revision`, добавляемый после компиляции | Сейчас `version.txt` содержит `0.1.0`, и его тег перезаписывается на каждом push. SHA-тег и сохранённый digest позволят однозначно найти сборку для отката. Выпуск неизменяемой версии лучше привязать к release/tag. |
| Высокий | `actionlint` и ShellCheck при изменении workflow/scripts | Проверять ошибки expressions, job outputs и shell до merge. Обычный YAML parser не проверяет семантику Actions. Локально эти проверки уже выполнены; в CI их пока нет. |
| Высокий | Проверка production build в PR: `CGO_ENABLED=0 go build -trimpath` и `--check` с временным `DATA_DIR` | Race-тесты не заменяют проверку статического production binary. Это закроет часть пробела до merge без возврата двух Docker-сборок в каждый PR; время дополнительного шага нужно измерить. Dockerfile по-прежнему проверяется после merge согласно текущему процессу. |
| Средний | `govulncheck` и обновление Go с синхронизацией `go.mod` / Docker `GO_VERSION` | Уязвимости бывают и в стандартной библиотеке. Отдельная регулярная проверка и сканирование на смене toolchain не удлинят каждый PR; результат аудита уязвимостей пока отсутствует. |
| Средний | Защиту обязательного `test` распространить на администраторов | Сейчас `enforce_admins=false`, approvals=0. Для одного сопровождающего можно оставить 0 approvals, но исключить случайный обход CI. Это настройка GitHub, она не менялась. |
| Средний | Очистка старых `ci-<run>-<attempt>-<arch>` тегов в Docker Hub | У каждого push остаются два промежуточных тега. Retention в Actions их не удаляет; нужен отдельный срок хранения с сохранением release digests и окна отката. |
| По измерениям | Экспорт Go compiler cache из Docker build | `type=gha` кеширует слои, но не содержимое cache mount. В более раннем логе после изменения кода одна компиляция amd64 занимала 14,2 с. `buildkit-cache-dance` добавляет упаковку и передачу кеша; сначала сравнить его стоимость с этой компиляцией. [Ограничение и официальный пример Docker](https://docs.docker.com/build/ci/github-actions/cache/#cache-mounts). |
| По измерениям | Пропуск Docker при изменении только документации/тестов | Экономит два build jobs и publish, но требует корректного baseline последней опубликованной сборки. Нельзя бездумно сравнивать только `event.before`: предыдущий release мог упасть или быть вытеснен из очереди новым push. Обязательный `test` должен возвращать статус и для docs-only PR. |
| Низкий | Repository policy обязательного SHA pinning и ограничение списка Actions | Сейчас `allowed_actions=all`, `sha_pinning_required=false`. Workflow уже закреплён по SHA; policy защитит будущие изменения. Требует доступности настройки для аккаунта. |

Для небольшого пакета сейчас не нужны разбиение тестов на несколько runners,
матрица нескольких Go-версий или self-hosted runners: дополнительные setup и
кеши увеличат накладные расходы. Снимать race detector ради времени не требуется.
Существующий `fail-fast: false` позволяет получить диагностику обеих архитектур
за один запуск; экономия от отмены соседней короткой сборки невелика.

Concurrency оставлен без изменений. По правилам GitHub в группе по умолчанию
сохраняется один pending run; следующий заменяет его. Поэтому это публикация
последнего состояния `main`, а не гарантия отдельного релиза каждого коммита.
Если потребуется выпуск каждой версии, стоит перейти к явным release tags и
соответствующей очереди. [Семантика concurrency](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency).

  daemon не подключился к опубликованному loopback-порту. Это ограничение
  локальной проверки; временные контейнеры и теги удалены. Внешние registry
  использовались только для чтения.
- Доставка изменений отслеживается в [PR #49](https://github.com/mitetenov/tg-railway-monitor/pull/49).
  После исправления gitlinks нужно дождаться успешного CI на финальном коммите;
  после merge — отдельно проверить Docker build/cache и публикацию обоих
  manifests в Docker Hub. Ускорение прогретого Linux CI ещё не измерено.
